multised (slim)

Harmonised marine-sediment trace-element data from five sources

multised assembles a database of marine-sediment trace-element measurements from five external sources, harmonises them into a common schema, and progressively quality-controls the result. This site documents the slim stage: five per-source databases that share one common schema, together with the quality-control and marking work performed on them.

Data sources

Source Origin Notes
Mareano Norway / IMR Norwegian cruise data.
Vannmiljø Norway Norwegian environmental monitoring.
ICES-DOME International Rich sediment-composition data.
MUDAB Germany German marine environmental database.
4Demon Belgium Compiled historical Baltic/North Sea data (Belgian).

Each source was first parsed into a per-source pilot database (documented on its own pilot site), then reshaped into the shared slim schema used here.

Pipeline generations

The data moves through four generations, each one SQLite database per source until the final merge:

  1. pilot: each source’s raw files parsed into a per-source database whose table structure follows that source. Documented on the individual pilot sites: Mareano, Vannmiljø, ICES-DOME, MUDAB, and 4Demon.
  2. slim (this site): every source reshaped into the same seven-table schema, then annotated with quality-control and marking flags. The underlying values are untouched; suspicious records are flagged, not deleted, so they can be reviewed.
  3. clean: the flags are applied (uncertain rows removed), units are harmonised, and normalisation (Fe/Al) and grain-size analyses are run.
  4. merged: the five clean databases are combined into a single database for the background / pristine-sediment analysis.

What this site covers

The slim schema, the quality-control flagging, and the construction of the clean databases are all documented here, grouped in the navigation bar:

DB Design

  • DB Schema (Slim): the common seven-table schema, the entity-relationship diagram, and a per-source column comparison showing which columns are shared and which are source-specific.
  • DB Schema (Clean): the clean database table layout.
  • Database Downloads: download links for the five slim SQLite databases.

Flagging (the quality-control and marking work)

  • Class Summary: the measurand categories (target, reference, organic, composition) that later steps read.
  • Unit Conversion & Range Check: the standardised value/unit and the per-element plausible-range flag.
  • Common Flags: the flags shared by every source (invalid values, duplicates, below-LOQ, multi-layer, weight basis, and more).
  • Source Specific: each source’s native leftover flags that the common flags do not cover.

Grain Size

  • Sample Fraction (matrix): whether each sample is a whole (bulk) sediment or a sieved fraction.
  • Fines (<63 µm): deriving the clay + silt fines fraction, including the noisy-curve correction.

Clean Databases (how the QC-passed end product is built)

  • Overview: the three-step clean stage and what the cleaning removed.
  • Harmonisation, Cleaning, and Grain-size Tables: the individual steps.
  • Cleaning Summary: chemistry counts before and after cleaning, overall and per element.
