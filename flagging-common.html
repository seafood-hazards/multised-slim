Common Flags

Common flagging columns shared by all five slim databases

After each source is reshaped into the common slim schema, a series of flagging steps annotates the data for quality control and review. Every step adds columns; it never changes or deletes a value. Suspicious or redundant records are marked so they can be inspected; the actual removal of unnecessary rows is a later Data Cleaning step, performed once the grain-size analysis is complete.

This page covers the common flags: the columns that all five sources end up with, applied the same way everywhere. The measurand classes and supporting-data availability are on the companion Class Summary page; the source-native flags that only some sources report (e.g. detection flags and outlier flags) are summarised on the Source specific page. Each section below gives a short description followed by a cross-source count table, computed directly from the current slim databases.

1. Invalid values

Adds an area_flag to site and an invalid_flag to measurement. A site is flagged outside Europe when its coordinates fall outside the European seas of interest. A measurement is flagged negative when its value is below zero, or over-range when it exceeds the physical ceiling of 100 % of the sample mass for its unit (e.g. a mg/kg value above 1,000,000). These are candidates for review, not automatic deletions.

2. Duplicates & technical replicates

Adds a dup_flag to measurement. Records sharing the same location, date, depth, element and unit are grouped: if the value is also identical the row is a duplicate; if the value differs it is a technical replicate. Both are kept for now and flagged for the clean stage to resolve.

3. Multi-layer samplings

Adds n_layers and multi_flag to event. An event with more than one subsample is a multi-layer sampling (e.g. a sliced core), while a single depth interval is a single grab. This is derived from the data, since the same gear yields both. The last column is the largest number of layers seen in any single event.

4. Below detection / quantification limit

Adds a below_loq flag to measurement, folding each source’s own detection flag (Mareano below_lld, Vannmiljø operator, the ICES qflag, 4Demon limit_flag) into one common marker. A value of 1 means the measurement is an uncertain “less-than” reading below the limit of detection or quantification, the main set of rows to remove in the clean stage.

Source Measurements Below LOQ Share
Mareano 41,789 4,583 11.0%
Vannmiljø 107,867 2,339 2.2%
ICES-DOME 158,858 2,361 1.5%
MUDAB 63,642 1,312 2.1%

5. Below limit (numeric cross-check)

Adds a below_loq_num flag to measurement: a numeric check that compares each value against the method’s own detection/quantification limit (LOQ, else LOD/LLD), as a cross-check on the label above, since a source’s detection label can be wrong. A value below the limit is flagged 1; at the limit exactly it defers to the label; a value above it is 0. Where the method table records no numeric limit the value cannot be assessed and the flag stays NULL (all of 4Demon, most of Vannmiljø).

The Missed by label column counts values the numeric check flags as below-limit that the source did not label, the errors this step is meant to catch.

6. Dry / wet weight

Adds a weight_basis flag to measurement, harmonising each source’s stated sample weight basis into dry or wet weight. It is read from the source’s own signal: a basis column (ICES-DOME / MUDAB / 4Demon) or the unit suffix (Vannmiljø mg/kg dw); Mareano reports everything on a dry-weight basis. Only chemistry (target / reference / organic) is classified: the counts below are over chemistry measurements, and grain-size composition is left unset (the dry/wet distinction is a concentration concept, handled separately for grain size). Dry weight is the sediment standard, so the few wet rows are the ones to review.
